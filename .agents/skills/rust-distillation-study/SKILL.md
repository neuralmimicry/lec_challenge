# Rust local distillation studies

Read `AGENTS.md`, `agents/PLAN.md` and the relevant public types in `src/study.rs`, `src/experiments.rs`, `src/distillation.rs` and `src/teacher_evidence.rs`. Keep application logic, numerical training, evidence verification and tests in Rust. The pinned upstream BitNet C++ inference engine is a documented interoperability exception; it is not a trainer.

Resume validated work by default. Search freezes its engine SHA; `examples/platform_launch.rs` resolves the original executable under excluded `state/engines/`. Experiment state retains its original worker executable, immutable arm request and step reservation. Do not replace either with a later Cargo output. Changing a method, token window, source, checkpoint, teacher, optimiser setting or seed needs an explicitly new protocol/output. Transient RAM/VRAM availability changes dispatch capacity, not the original plan. Corrupt cache entries fail closed; they are not permission to regenerate favourable observations.

Teacher selection uses the complete original development pack and a separately frozen fresh confirmation pack. The sealed assessment set cannot tune the roster or an experiment. Keep the strongest measured fallback if the quality target is unmet, label the shortfall and continue the bounded declared alternatives when online. Explicit offline means no HTTP, including metadata requests. Downloaded model count is not qualified model count; quantisations of one original source remain one model.

Only remove owned, inactive model weights through `teacher_search` pruning. Protect the assessment base, student bases, active leases, retained teachers and selected checkpoints. Keep publisher manifests, licences, prune authority and all measured outputs. An absent weight is rehydratable only with its durable owned deletion record; a present corrupt weight remains an error. Credentials are ephemeral stdin/environment only and must never appear in command arguments, code, reports or caches.

Create training bundles through `teacher_evidence::collect` and `load_verified`. These reconstruct actual train-only generations and independent container verdicts. Reference solutions, development comparisons and synthetic numerical QA are not training examples. Empty, truncated, errored or quarantined candidates cannot be positive samples. Process/context/tool trajectories need their actual extra generations and observations; a grader result alone is not a trajectory. On-policy and self-distillation need checkpoint-bound student rollouts, teacher feedback and regrading before their capabilities become available.

Distillation axes are composable losses, example content and organisation. Check each arm against the particular teacher/student pair. Sequence learning needs verified outputs; tensor losses need actual native targets acquired before the optimiser; feature and attention transfer use exact assistant byte anchors; direct token transfer needs matching semantic token IDs. Qwen heads may have different padding even with the same tokeniser vocabulary. Preserve the complete probability mass using the declared residual-category mapping and record its diagnostics. Do not silently crop logits, discard a top-k tail or claim cross-tokeniser KL without an implemented alignment.

Context distillation requires different conditioning: retain the richer original teacher prompt in provenance and capture, while training the student on the declared shorter original task prompt. Record that transformation and align assistant byte spans across the different prefixes. DPO evaluates chosen, rejected and frozen-reference sequences under one common declared preference prompt; generation prompts remain separate evidence. After windowing, verify the actual retained prompt tokens and original start position still agree for both responses. A shared original string does not prevent independent truncation from changing the conditioning. Comparing conditional likelihoods from different prompts is not standard DPO. A fixed trusted grader/revision trajectory does not establish arbitrary tool selection, and an ordered teacher curriculum does not establish a teacher-assistant architecture bridge.

Sandbox quarantine verdicts remain immutable. A separately verified content-role classifier may admit an executed oracle-only failure as a negative or a trusted compiler failure as bounded correction context. Neither becomes a positive solution. Prohibited operations, missing audit evidence, incomplete output and infrastructure errors cannot become trusted negatives or invented tool observations. A passing corrective teacher generation needs its own complete independent container verdict. Continuations link earlier frozen student attempts rather than resampling them to find a favourable failure.

An arm's realised steps must exercise every named teacher/content axis. Save the exact sample order, assistant loss windows, loss components, optimiser moments and numerical evidence at every committed step. A shortened assistant window is an explicit operator-screening fidelity; it does not establish useful task learning. Full-fidelity examples use their declared sequence policy and retain rejected overlength counts. Require finite loss, nonzero reachable adapter gradients, changed tensors, frozen base and an independent evaluation-process reload.

For BitNet, retain the official packed-weight interpretation, scale semantics, ReLU squared, subnormalisers, grouped attention and original tokeniser. Latent low-rank updates enter the ternary quantiser during the forward pass with an actual straight-through gradient. An ordinary floating LoRA branch or post-training quantisation is not ternary training. Require changed effective ternary decisions as well as changed latent tensors, and verify their exported/reloaded identity. Use the declared BitNet-specific learning rate rather than silently changing it after a flat update. Compare the actual trained checkpoint and inference engine; native correctness QA and a C++ serving benchmark are distinct evidence.

BitNet validated ranking additionally requires the schema-2 numerical receipt: reconstruct the fixed synthetic prompt/token protocol and unchanged 0.10 tolerance from full Rust log probabilities and original native top-16 responses, bound to this exact checkpoint, exporter and native engine. Export/tokeniser parity and agreeing top predictions cannot replace numerical equivalence. Missing, failed or stale receipts preserve descriptive task scores but exclude the arm from validated selection. A new native quantisation patch needs its own immutable engine and measurement; never rewrite an earlier failure.

Use the scheduler's atomic CPU/RAM/VRAM reservations and per-student/fidelity profiles. Prewarming teacher tensors can release GPU capacity before CPU training, but `CacheOnly` must reject any missing or invalid target. Do not reserve zero GPU memory while a worker may acquire a teacher. Respect affinity/cgroups and measured memory headroom; the current eight-GiB laptop can host only one large teacher at once.

New CPU experiments may select the reviewed AVX2/FMA/F16C or NEON build profile automatically. Freeze its exact compiler flags/cfg and host requirements with the executable; a portable override changes new protocols only. Historical runs retain their original executable and CPU contract. Teacher tensor cache acquisition and cache-only training must use the same pinned executable because its identity is part of the target fingerprint. Cross-compilation and compiler-cfg probes do not establish execution on another architecture.

Screen isolated operators first, then use the declared remaining budget for preregistered seed controls and actual mixed objectives. A catalogue containing mixtures is insufficient if the selector never dispatches them. Preserve old frozen selections when extending future coverage. Pressure preflights and ordinary grading coordinate through the native runtime lease; historical binaries need manual isolation because they do not acquire it. Keep ABI policy and host-controller versions explicit, preserving historical policy bytes and reports. Candidate lifetimes need an independent runtime ceiling and owned crash recovery as well as normal asynchronous cleanup.

Rank only complete, independently reverified development observations under matched task, seed, decoding and grader settings. Retain all failures in denominators, and report queued/unavailable arms alongside measured ones. “Best tested” is bounded by the executed catalogue, budget, source set and uncertainty; it is not a global optimum or a SHIP decision. The assessment's strict provider provenance and source-cluster promotion gate remain separate.
