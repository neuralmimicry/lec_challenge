# Principal-engineer cold walkthrough

The implementation is native Rust. Start by separating what exists from what is still missing: real pinned Qwen inference, full-model synthetic-gradient QA, container/security probes and local endpoint evidence exist; three real teacher recordings, a provider-derived dataset, assessment adapters and a real improvement result do not. `reports/drill.md`, `reports/eval.json` and `docs/limitations.md` are the current evidence register. An INVALID evaluation is not a statistical NO SHIP result.

The design claim is narrow: complementary verified teacher solutions may improve a specialised student's pass@1 and reduce cost. This does not establish general superiority over frontier models. If every teacher fails, selected-output SFT supplies no verified corrective answer without extra verifier/task/search signal.

## Code map and invariants

| Topic | Exact entry points and what to explain |
| --- | --- |
| Purchase transaction | `src/ledger.rs`: `Ledger::claim_and_reserve` uses a SQLite immediate transaction, a unique semantic request key and integer nanodollars. It checks round/task/provider/model upper liabilities, including in-flight reservations, before dispatch. `Ledger::record_round_plan` and `src/fleet/config.rs::build_round_plan` bind completeness to intended jobs and permitted failover keys. In `src/fleet/runner.rs::FleetRunner::complete_on`, each retry passes rate limiting and reservation again. |
| Crash and UNKNOWN window | `Ledger::publish_artifact` fsyncs a content-addressed response before `Ledger::finish` records completion. `Ledger::lookup_request` reuses completed evidence before another transport call. `Ledger::mark_unknown` / `recover_interrupted` retain the upper liability and block further purchases when acceptance is uncertain. `src/main.rs::collect` holds the exclusive orchestrator lock before recovery. A provider accepting a request before the response becomes durable cannot generally be made exactly-once by a local database; reconciliation, not automatic repurchase, is required. |
| Roster, retry and replay | `src/fleet/config.rs::ProviderConfig::validate_enabled`, `prepare`, `request_identity`; `src/fleet/runner.rs::retry_delay`; `src/fleet/transport.rs::ReplayTransport::load_with_policy`. Configuration owns business/model identity, token caps, prices and rights. Canonical keys include the full request and intended sample slot. Replay requires the exact real recording and has no live-network fallback. A 429 changes scheduling; it does not grant another budget. |
| Source separation | `src/tasks.rs::corpus`, `validate_corpus`, `write_corpus`; `src/curate.rs::index`, `check_origin`, `validate_dataset`. There are 96 contracts, split 48/16/32 by complete source groups. Renaming a task or changing a seed does not create a new lineage. The immutable index is checked against the compiled catalogue. Shared AI authorship and familiar algorithms weaken source independence and novelty claims. |
| Hidden-test boundary | `src/sandbox.rs::grade` assembles public/private cases on the trusted controller, sends only JSON inputs and compares typed responses against controller-owned expected values. Candidate code is compiled in its fresh container. Hidden inputs must be visible to solve a task; oracle code and expected answers remain outside. Candidate exit zero, fake success JSON, missing lines or stdout resembling a test report cannot award success. `verify_report` binds verdicts to code, policy/image, cases and audit hashes. |
| Isolation and trusted tracing | `src/sandbox.rs::base_command`, `preflight`, `timeout_probe`, `stop_container`; `sandbox/audit.rs::run`, `trace`, `string_at`; `sandbox/seccomp.json`. Non-root UID 65532, read-only root, no network, dropped capabilities, no-new-privileges, bounded tmpfs/PIDs/CPU/memory and host timeout are combined. The trusted Rust ptrace supervisor runs inside the container, outside the candidate process; it rewrites prohibited native syscalls to fail and records exact targets/results. The host verifies that evidence. Preflight inspects effective cgroups and executes OOM, process-pressure and timeout probes. This is Linux x86-64 shared-kernel isolation, not a proof against every kernel exploit. |
| Curation and provenance | `src/curate.rs::validate_evidence`, `canonical_code`, `code_similarity`, `curate`, `validate_dataset`. Passing controller evidence, real recording identity and approved permission decisions are rechecked; lineage/specification similarity and canonical Rust syntax supplement exact hashes. Winner selection uses recorded cost and deterministic tie-breaks. Semantic equivalence is not solved perfectly. `src/cli_demo.rs::demo_actual_round` retains original validated training provenance when regrading creates new run IDs; it does not fabricate stable run IDs. |
| Actual labels and gradients | `src/model.rs::chat_prefix`; `src/train.rs::encode_sample`, `assistant_loss`; `src/model.rs::QwenModel::hidden`, `FrozenMatmul::bwd`, `frozen_linear`. The original chat-tokeniser offsets select only assistant code/EOS targets; prompt and boundary-straddling tokens are excluded. Only selected positions reach the vocabulary loss. Tensor RoPE, RMS normalisation and softmax retain backward support. Frozen GEMM returns the exact input derivative but no base-weight gradient. The base stays constant; rank-eight query/value adapters in all 24 layers are trainable. |
| Optimiser and checkpoint resume | `src/train.rs::run`, `ResumableAdam::{load,update}`, `save_tensors`, `validate_checkpoint`. Dataset validation precedes optimiser construction. Finite loss, present/nonzero adapter gradients, finite updates and changed tensor hashes are required. Each durable step stores adapter/moment safetensors and a manifest before the atomic progress pointer moves. A kernel-released process lock excludes concurrent trainers. Resume requires the exact data/configuration/index and deterministic sample order. Unit tests cover numerical Adam continuation; missing real provider data still prevents an assessment round. |
| Evaluation and gate | `src/evaluate.rs::run_split`, `verify`, `verify_split`, `verify_generation`, `gate_files`; `src/gate.rs::decide`, `intervals`. Complete artifact-bound outcomes are required for every expected task/seed. Model errors stay in the denominator; infrastructure failures invalidate the evaluation. Average decoding repeats within tasks, tasks within sources, then sources equally. The gate uses a two-sided source-level t interval and source-cluster bootstrap; both lower bounds must exceed +2 percentage points, with non-regression/security checks. Eight source groups, not the 96 task-seed outcomes, determine the independent sample size. |
| MDE and sealed access | `src/cli_demo.rs::demo_freeze`, `demo_development_power`, `demo_evaluation`; `src/gate.rs::simulate_power`. All four adapters and the primary candidate freeze before development evaluation. Development discordance/source effects and a fragile ICC estimate inform a declared sensitivity grid; the power/calibration hashes freeze before held-out access. Simulation uses the configured gate, seeded trials and Monte Carlo uncertainty. No tested effect reaching 80% means above the tested range, not an invented precise MDE. No real development calibration exists yet. Complete caches are verified; interrupted preregistered evaluation is explicitly blocked rather than silently rerun. |
| Fixtures versus real controls | `src/drills.rs::actual_control_cases`, `gate_fixtures`; `src/fleet/local_drills.rs::{run_local_drills,run_recorded_drills}`; `src/train.rs::TrainingPurpose`. Synthetic score/transport tests establish decision/recovery invariants only. The actual degraded adapter must lose, the actual overfit adapter must gain on train and lose on held-out, and the fixed seed pair must be interpreted honestly. A control producing another pattern leaves its drill incomplete. Never search held-out seeds/targets until the desired pattern appears. |
| Rights and costs | `docs/rights.md`, `config/fleet.toml`; `ProviderConfig::validate_enabled`; `src/cost.rs::{export,cost_per_point,break_even_volume}`. Output ownership is not sufficient permission to train a competing model. Account/model terms, retained document hashes, exact prices and billable reasoning caps must be cleared; all three providers currently remain disabled. Historical acquisition, replay's new spend, cash/credits and compute allocation are separate evidence. A free or owned machine is not zero compute. Cost per point divides a complete round total by `100 × rate_gain`; non-positive gain is N/A and an inconclusive gain supports only a descriptive ratio. |
| Serving and rollback | `src/serve.rs::{run,generate,publish_route,stage_evaluation,stage_canary,route_generate,rollback}`. One immutable checkpoint process has a bounded model queue, bounded body/token limits and a genuine health inference. Staging a five-per-cent canary recomputes the verified checkpoint gate and checks endpoint identities; controls and NO SHIP remain evaluation-only. Atomic generation-checked routing changes new requests while dispatched requests drain. A candidate operational error triggers the declared one-error rollback threshold. Model cancellation is cooperative at token boundaries; hard compute pre-emption requires a process supervisor. |

In the power simulator, task effects reuse a common source draw with probability `sqrt(rho)`. Two tasks share that draw with probability `rho`, giving the declared pairwise source correlation; using `rho` as the reuse probability would instead produce `rho²`. A Monte Carlo moment invariant checks this construction. Reduced simulation settings are diagnostic and must not replace the full frozen gate configuration in a promotion claim.

## A 60-minute live session

| Time | Review or requirement change | Likely pressure point and defensible response |
| --- | --- | --- |
| 0–10 minutes | Trace one request through reservation, 429, failover, response publication and restart. Then lower the round budget while calls are in flight. | Follow ledger rows and `cost_upper_nanos`; completed work is reused and outstanding upper liabilities still count. Explain the UNKNOWN acceptance window rather than promising remote exactly-once billing. |
| 10–20 minutes | Add a fourth provider, a reasoning model or a different output-token parameter. | Start with `ProviderConfig`/`prepare` and transport response parsing. Reject the model until full billable output is capped, token semantics/prices and output-training terms are explicit. Adding an alias behind an existing business does not add an independent provider. |
| 20–30 minutes | Permit candidate file reads, subprocesses or a new architecture. | The candidate ABI, ptrace path/syscall policy, seccomp allow-list and adversarial probes need deliberate changes. Read-only hidden tests would disclose them. ARM support needs a separate audited register/syscall decoder; do not weaken a failed preflight to make a demo run. |
| 30–40 minutes | Double sequence length, switch the student, or resume a killed training process. | Token limits affect filtering, activation/vocabulary memory and CPU time. The current pinned Qwen architecture, tokenizer/template, frozen projection and checkpoint base hashes are explicit assumptions. Resume uses the same data/configuration/optimiser moments; changing them is a new round. Use the labelled 512-token resource QA before capacity claims. |
| 40–50 minutes | Increase decoding seeds or reduce the promotion margin after seeing the result. | More seeds reduce measurement noise but add no independent sources. The frozen gate/configuration rejects the changed plan. More source groups require new task lineage, held-out index, calibration/power assumptions and a new evaluation; a favourable extra seed is not a legitimate promotion strategy. |
| 50–60 minutes | Increase canary traffic, inject latency/errors, or ask for a commercial break-even figure. | Routing generation and immutable IDs make rollback observable. The local same-base alias smoke proves mechanics, not candidate quality or production-scale SLOs. Break-even remains unavailable until comparable verified quality, acquisition cash and serving/compute costs are measured. |

For the final account, state the incomplete items plainly: no real teacher acquisition, no provider-derived assessment checkpoint, no real held-out learning claim, and no full disconnected replay containing those absent artifacts. The full synthetic-gradient and endpoint reports are useful engineering evidence; they do not close those gaps.
