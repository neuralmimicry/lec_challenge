## Corpus and statistical limits

The 96 local Rust contracts are grouped into 24 distinct practical source packs and split 48/16/32 by whole source. They share AI authorship, task-writing tooling and common algorithmic knowledge. Those facts weaken an independence claim; source groups are declared design units, not independently audited human authors or proof of pretraining non-exposure. Public expected examples are written separately from oracle code; private values use the oracle. Independent interval/fraction properties give extra checks, but a second independent oracle for every contract remains review work.

Lineage, exact specification hashes, lexical similarity and canonical Rust syntax reduce contamination and duplication. They do not prove semantic novelty. Reworded tasks with falsified lineage and sufficiently different wording can evade lexical screening. Similarity hits are conservative review blocks; no automatic embedding system establishes equivalence.

The primary held-out set has only eight source groups. Both the t interval and bootstrap can have fragile coverage under source dependence or skewed effects. Shared authorship may worsen dependence. The power sensitivity grid is a simulation under stated discordance/correlation assumptions; no real development-run calibration exists yet. More assertions and decoding seeds do not create more independent tasks or sources. A seed-only comparison may occasionally be significant and must be disclosed.

## Runtime and operational limits

The sandbox uses shared-kernel containers. Its original syscall decoder is Linux x86-64; the separately versioned portable policy implements x86-64 and ARM64 syscall tables, but actual ARM hardware execution remains unverified. It does not establish resistance to every kernel exploit or all future syscalls. The candidate ABI deliberately supports pure Rust functions using std/serde_json; process spawning, networking and arbitrary file access are prohibited. Trusted syscall traces prove the exercised probes, not every possible attack. Resource limits are verified by actual kernel probes on the tested host; another machine must pass those probes itself.

CPU generation cancellation occurs at token boundaries. A matrix multiplication cannot be interrupted from inside the model worker; a hard model-compute deadline requires process supervision. Candidate execution additionally needs its own independently enforced process-tree ceiling. Verification 007 failed the strict host-kill assertion, and separate diagnostics found that the old native deadline included runtime setup while the intended candidate timer started later. The separately versioned V3 controller/policy preserves those failures and has now passed fresh actual deadline, portable and orchestrator-crash tests. Verification 009 passed all three actual container checks. These results bind the measured executable/image/platform; earlier or other-platform observations cannot certify them. CPU/queue/timeout QA demonstrates bounded serving mechanics at low volume, not production-scale latency or availability.

No 12 GiB GPU assumption is used: the observed card has 8 GiB. Both native CPU/F32 and explicit CUDA inference have run; the actual full-context conventional training rounds use CPU/F32 and separately captured CUDA teacher targets. Automatic resource discovery is implemented for amd64 and ARM64, but execution on another architecture and other accelerator backends remains unverified. Training/inference timings are workload measurements on one laptop; some jobs overlapped and were not isolated throughput benchmarks. The 512-token synthetic gradient process peaked at 7,967,212 KiB RSS in `reports/native-gradient-512-time.txt`. Full provider-round and sustained-serving peak memory, throughput and compute/energy allocations remain unmeasured.
