## Source audit and implemented contracts

The CLI freezes a catalogue in `study/planner` / `experiments`; dispatch calls
`study::prepare_selection` before reserving resources or updates. This delegates
to the existing `preflight_eligibility`, whose selector is also used by target
prewarming and the optimiser. Catalogue capability applicability alone is not
executable data eligibility. A rejected dispatch retains its reason without
starting a numerical process or consuming optimiser steps.

Schema-2 selection retains exact sample IDs/order, input hashes, assistant byte
spans and prediction positions, EOS, content/source provenance, objective/target
requirements and exclusions. The worker compares its reconstructed receipt with
the dispatch receipt before optimisation and freezes it with the checkpoint.
Checkpoint verification independently reconstructs order and encodings. Cache-only
preflight verifies existing tensor bindings without acquisition or cache creation.
The new trace binding additionally contains the actual teacher sequence.

The current supported bounds are **1–64 updates, 4–1,024 sequence tokens including
EOS, rank 1–32 and learning rate 1e-7–0.01**. Configuration and worker share their
validator. Teacher and student use the existing frozen cap, with separate
measurements and original templates/tokenisers. An overlength privileged teacher
is excluded before loading weights; it is never replaced by the shorter student
prompt. Collection context/output and evaluation generation budgets are separate.
There is no new 2,048-token training capacity in this repair. Full teacher attention
and resident trace payloads have independent 512 MiB checks; the existing 8 GiB
target-cache budget remains enforced.

Preference-only schema-2 requests resolve chosen IDs to their actual content,
including process/context corrections. Both responses retain the verified common
conditioning and existing unequal-window rejection. Schema 1 retains its original
specification translation for historical readers; it is not silently repaired.

The native adapter is the existing Qwen q/v LoRA path with alpha/rank scaling.
Training and inference use the same projections and scaling. Assistant labels
predict the next complete assistant token at the preceding position; prompt and
boundary-straddling tokens are masked, and EOS is supervised separately. No padding
positions are introduced. Frozen base projections retain input gradients without
optimising the base. The inference loader previously loaded a base-only model and
then another base with the adapter before replacing the first; it now constructs
the runtime directly around the adapted model, avoiding simultaneous duplicate
base residency.

Teacher targets are detached; student features retain their gradients. Existing
middle-layer selection, byte anchors, fixed channel pooling, row normalisation,
causal attention and normalised anchor attention are retained. Non-identical
feature/attention regression fixtures check finite nonzero student gradients,
teacher detachment and sensitivity to row permutation. Full-vocabulary KL still
retains semantic IDs and all residual mass. No top-k approximation is added.
These checks do **not** identify the cause of the historical collapse.

New Qwen feature runs freeze observational health checks at updates 1 and the last
update (64 tokens, 30 seconds, first realised train sample, no automatic stop).
`quick.health_check` / `full.health_check` can explicitly declare up to four
checkpoints and a stop policy. Failed and interrupted checks retain their records;
resumption cannot silently skip an absent committed observation. Checkpoint
verification binds the actual prompt, runtime, adapter and original generation.
No old feature-only objective receives SFT automatically. Optional
`quick.objective_weights` / `full.objective_weights` change only already-declared
objectives, for example `sequence_sft = 1.0` and `hidden_feature = 0.1`; such a new
experiment still needs matched SFT controls with identical rank, rate, steps,
sample order and complete seed groups.

`worker-progress.json` preserves completed training/export/reload independently of
evaluation. `evaluation-process.json`, exit evidence and serialisable
`evaluation-failure.json` preserve later attempts. Reasons distinguish split,
checkpoint, invalid evidence, incomplete generation, inference timeout, grading
infrastructure and other unhealthy completion. Accepted evaluations still pass
the complete raw-generation/sandbox/checkpoint verifier; strings and exit zero
cannot substitute for it. Failed generations and grades stay in the denominator.

New plans can independently freeze `--student-device`, `--evaluation-device`,
`--evaluation-dtype` and `--evaluation-cpu-threads`. Teacher capture retains its
own execution arguments. Phases are serial within a worker; reservations cover
the largest teacher/optimisation/evaluation VRAM requirement and are checked
against actual free VRAM at planning and dispatch. Evaluation model threads use
the frozen CPU reservation minus one (minimum one), leaving grading capacity.
BitNet remains CPU/F32 and is inapplicable to an incompatible global runtime.
Actual loaded execution metadata and comparison thread identity remain enforced.
One shared, model-free support check rejects CPU/F16 and CUDA requests from a
CPU-only executable before planning/selection. The actual loader uses that same
check; GPU context creation still independently fails if the requested device is
unavailable. Historical evidence readers do not need to allocate a GPU merely
to reconstruct an old report. NLL-only diagnostic aggregates use an unknown
coding score, rather than reporting an unmeasured zero.

Schema-1 plans, requests, manifests and selections remain readable with their old
semantics. New study plan/spec/freeze/manifest schemas are 2; the success-only
worker outcome and existing frozen evaluation schema remain 1. The new partial
progress schema is 2, rejection and diagnostic schemas are 1. Selection schema 3
excludes zero-score and incomplete-seed groups from automatic continuation.
Nonzero descriptive scores alone still cannot demonstrate improvement. Runtime,
source, limits, objectives or decoding changes require a fresh experiment or
evaluation attempt. Cache fingerprints include the engine and sequences; old
tensor evidence is never relabelled for the repaired executable.

## Operator sequence

These commands use native CLI names. Diagnostics never download models. Use an
existing verified checkpoint, or substitute a verified worker `--request`.

```bash
test ! -f state/lec-sm00-env.sh || source state/lec-sm00-env.sh
cargo build --locked --offline --release
target/release/lec-distil assets-doctor --base offline_bundle/base --offline
target/release/lec-distil sandbox-doctor --archive-directory offline_bundle/images
target/release/lec-distil study-diagnose-training \
  --checkpoint reports/local-study/native-full-sft-seed1729 --offline
target/release/lec-distil study-diagnose-training \
  --checkpoint reports/local-study/native-full-sft-seed1729 \
  --nll --generate --maximum-examples 1 --max-new-tokens 512 \
  --maximum-seconds 900 --cpu-threads 4 --device cpu --offline \
  --output reports/repair-20261022/selected-training-new-attempt
```

Numerical output must be fresh. The parent freezes the exact protocol, supervises
a new process under the total deadline, streams sample progress and preserves
per-example files on timeout. Each phase loads one model at a time. Base and
reloaded adapter use identical prompts, tokens, seed 1729, temperature 0.2, top-p
0.95 and runtime/thread allocation. Generation requires complete in-capacity
training sequences; assistant windows cannot be silently substituted. `--nll`
and `--generate` are independent operations. NLL, accuracy and EOS likelihood
are recorded per example and in aggregates, with masks/positions. DPO chosen and
rejected teacher-forced measurements retain their common conditioning. Generated
Rust is graded only after full sandbox preflight and only inside the sandbox.
Without `--train-updates`, these operations perform zero updates. Explicit
`--train-updates 1` (up to 3) additionally requires `--nll` and a verified fresh
request whose frozen budget is exactly that number of updates on one complete
selected SFT example. It rejects other objectives, multiple selected examples,
windows, changed budgets and existing checkpoint outputs. It checks live
resources and takes the scheduler's resource lease; it never starts a whole
catalogue or a development evaluation. The total diagnostic deadline includes
preparation time and the child is killed if its parent disappears.

The native preparation boundary writes the same independently checked request
and selection used by dispatch, without starting training:

```bash
target/release/lec-distil study-prepare-arm --study NEW_STUDY_DIRECTORY \
  --arm ARM_ID --profile quick --output NEW_REQUEST_DIRECTORY --offline
target/release/lec-distil study-diagnose-training \
  --request NEW_REQUEST_DIRECTORY/request.json --train-updates 1 \
  --nll --generate --maximum-examples 1 --max-new-tokens 512 \
  --maximum-seconds 900 --cpu-threads 4 --device cpu --offline \
  --output FRESH_DIAGNOSTIC_DIRECTORY
```

Evaluation-only recovery already exists and remains a fresh protocol bound to the
original checkpoint, without changing the failed worker outcome:

```bash
target/release/lec-distil study-evaluate --checkpoint CHECKPOINT \
  --base offline_bundle/base --student qwen --split development \
  --device cpu --dtype f32 --offline --output NEW_EVALUATION_DIRECTORY
target/release/lec-distil study-compare \
  --baseline MATCHED_BASELINE_DIRECTORY --candidate NEW_EVALUATION_DIRECTORY
target/release/lec-distil study-verify --evaluation NEW_EVALUATION_DIRECTORY \
  --expected-split development --expected-checkpoint ADAPTER_SHA256
```

Use the same explicit inference thread environment for matched baseline/candidate
processes. Existing comparisons reject changed engine, runtime, decoding, task,
tokeniser, base, grading or thread identity. Regenerate a matched baseline when
required. Only then consider a separately frozen new study; never tune the sealed
set or select a favourable seed.

For dependency-cache misses, use `cargo fetch --locked` in an explicitly online
preparation phase. `LEC_CARGO_ONLINE=1` permits online launcher builds;
`bootstrap-online` also expresses online intent. Explicit `--offline` overrides
that intent and preserves caches, models, ownership/prune records and markers.
An offline compilation failure supplies the preparation command without retrying
online. The launch tests use command fixtures and perform no network operations.

CUDA auto discovery rejects releases outside locked cudarc 0.16.6's table (including
13.3) before native compilation, separately checks the driver ceiling, then checks
the C++ compiler with a real minimal CUDA compilation. Explicit toolkit/compiler
choices are honoured if valid and otherwise fail directly. The build receipt binds
nvcc/compiler hashes, toolkit version, compute capability, local header overlay
and compile-check provenance. CUDA compilation is not GPU execution evidence.

The sandbox doctor reports UID/rootless state, active graph/run roots, effective
storage configuration and explicit configuration paths, tag/ID, policy and archive
verification. Temporary/foreign graph roots are flagged. Explicit restoration is
`sandbox-doctor --archive-directory offline_bundle/images --restore-archive`;
only the verified exact image is loaded into the active store. It never resets,
prunes or migrates a global store. A rebuilt image is a new identity; old plans
still require their original image. The doctor does not authorise grading.
`assets-doctor --quarantine-conflicts` explicitly renames corrupt/non-regular/file-
path directory conflicts; it cannot be combined with `--offline`. Valid payloads
and valid provenance manifests are not rewritten by bootstrap.
