# Native Rust adaptation and inference

The training path uses Candle in Rust throughout. It loads the actual 494,032,768-parameter Qwen2.5-Coder-0.5B-Instruct base at revision `ea3f2471cf1b1f0db85067f1ef93848e38e88c25`, its original tokenizer and Apache-2.0 licence. The upstream model safetensors SHA-256 is `f9523886352217ded3aeeef552b381af79d568c6d49a4b9e423288cea56b0a44`. Runtime loading checks every bundled asset; downloading is confined to the explicit online bootstrap command.

The implementation reproduces Qwen2 grouped-query causal attention, split-half rotary embeddings, RMS normalisation, SwiGLU feed-forward layers and the tied output embedding. The frozen base runs in CPU float32. Rank-eight LoRA is applied to query and value projections in all 24 transformer layers, initially using a random A matrix and zero B matrix. Alpha is 16. Base parameters are ordinary constant tensors; the optimiser receives only named adapter variables. No PyTorch, Python interpreter, renamed base checkpoint or training service is involved.

Candle's fast inference RoPE, softmax and RMS normalisation operations do not support backward propagation. This implementation deliberately uses their differentiable tensor equivalents. A full small-architecture unit test checks gradients through attention, rotary embeddings, normalisation and feed-forward layers. That random unit model is implementation evidence only; it is never labelled an assessment checkpoint or provider-trained model.

The no-tools, single-user branch of the pinned original Qwen chat template is rendered exactly, including its default system message and assistant generation prefix. Training tokenises the complete conversation and uses token byte offsets to select targets wholly within the assistant completion plus end-of-message marker. Tokens overlapping the prompt boundary are excluded. The prompt supplies context, but no prompt token is a loss target. Overlength examples are rejected and recorded rather than silently truncated. Every effective sample must have at least one supervised token. The vocabulary projection is calculated only at selected positions.

Training first validates the complete curator dataset manifest against the immutable held-out index. This occurs before model construction or optimiser initialisation. The validator requires passing trusted runs, provenance, permission decisions and source separation. The optimiser cannot be enabled by choosing a conveniently named dataset file. Missing real provider outputs remain a blocker; reference answers and generated fixtures do not replace them.

SFT uses one sample per optimiser step with a reproducible epoch shuffle, cross-entropy, AdamW and a global gradient-norm cap. The trainer requires finite loss, every adapter gradient to exist, a positive finite gradient norm and finite updated parameters. It writes the actual loss and gradient norm after each step. A deterministic seed of 1701 is predeclared; the second genuine adapter uses 1702 and identical settings. A seed-control comparison is interpreted from its actual evaluation, never assumed to be a null result.

Four predeclared configuration files select candidate, second-seed, deliberately degraded and overfit purposes. Every mode first validates the original provider dataset. The degraded control explicitly replaces the target with a correctly typed Rust function returning JSON null; the manifest names that target transform and retains the original dataset/provenance hashes. The overfit control retains the original correct targets and uses a longer, stronger training schedule. Neither manipulation guarantees a regression or the train-gain/held-out-loss pattern. Both controls are frozen before sealed access and their actual measured outcomes must be disclosed. A control-purpose adapter cannot authorise production canary traffic.

Each completed step has adapter safetensors, first/second-moment safetensors and a checkpoint manifest. Files are fsynced before the atomic progress pointer is updated. A process lock prevents concurrent trainers targeting one output directory and is released by the kernel after a crash. Restart loads only the last published state and validates data, configuration and tensor hashes. An unreferenced interrupted directory does not count as completed work. Finished checkpoint directories are immutable. The final manifest includes data/base/tokenizer/configuration hashes, seed, step count, filtering, gradients, losses, elapsed time and changed tensor hashes.

The base and adapter load into a fresh runtime for actual autoregressive generation. Inference uses a KV cache, deterministic nucleus sampling and explicit output/context/time caps. Empty, non-finite or failed generation is an error. Length-limited or timed-out output is marked incomplete and cannot receive a successful evaluation verdict. The endpoint exposes its tensor hash in every response. Timing out an HTTP request cancels queued work and requests cancellation at the next token boundary; a matrix multiplication already executing cannot be pre-empted. A process supervisor is required for a hard wall-clock limit on model compute.

## Serving and routing

Each server process owns one immutable checkpoint. `/health` includes checksum verification and output from a genuine inference smoke test. `/metadata` includes the checkpoint identity, limits and request/error counters. `/v1/generate` accepts a bounded request body and a bounded token count. A dedicated single model thread receives jobs through a bounded channel, keeping CPU work off Tokio executor threads and limiting both queue and concurrency. Queue saturation returns 503; deadline expiry returns 504. The server binds only to a loopback address.

Routing uses an atomic manifest naming immutable incumbent and candidate endpoints. A canary cannot be enabled by a statistics fixture or self-declared aggregate. Staging recomputes the gate from both complete checkpoint-bound evaluations, verifies artifacts through the integration verifier, checks endpoint health and matches tensor identities. Only SHIP permits the five-per-cent canary. Routing snapshots one manifest per request; rollback changes new requests while requests already dispatched drain on their original process. A candidate operational failure triggers rollback at the predeclared one-error threshold. The previous model and candidate metadata remain available for audit. Evaluation routing is explicitly selected and does not authorise production traffic.

## Evidence and limits

Actual measured smoke and invariant results are recorded separately in reports. A working gradient test proves the implementation can learn, not that the assessment student has improved. A real assessment round still requires rights-cleared recorded provider outputs, fully passing container grades, a validated dataset, two trained adapters and complete held-out evaluations. The deliberately degraded and train-overfit checkpoint controls must also be measured honestly; no target corruption strategy guarantees the required observed pattern. No checkpoint or improvement should be claimed until its artifacts exist.

Measured on this workstation, the pinned base generated a complete 29-token Rust function in 7.244 seconds after a 12.66-second load/checksum phase. A full-base 64-token synthetic tensor forward/backward/Adam update took 4.173 seconds after checksum validation, with finite loss 9.76363, gradient norm 7.31670 and adapter-change L2 0.08831. It exercised 540,672 trainable parameters across 96 adapter variables and passed safetensors round-trip/frozen-sentinel checks. Those two QA jobs overlapped, so the figures are observed timings rather than isolated throughput. No assessment checkpoint was saved by the synthetic test.

The larger 512-token synthetic QA supervised 256 positions and completed its measured update in 20.918 seconds; `/usr/bin/time -v` recorded 27.89 seconds for the whole process, 51.79 seconds user CPU, 11.32 seconds system CPU and 7,967,212 KiB peak RSS. Loss was 10.04124, gradient norm 7.32737 and adapter-change L2 0.08843. This tests the configured sequence ceiling on real weights, rather than extrapolating memory from the 64-token test. It remains one synthetic QA step; the complete four-adapter round and checkpoint evaluations have not been timed. At this observed step duration, hundreds of full-length CPU steps would take hours, so reviewers should distinguish full training from the explicitly labelled saved-checkpoint/cached-evaluation mode.

The actual base endpoint subsequently returned a complete 29-token function in 4.560 seconds. Twelve concurrent short-deadline requests produced ten 503 queue-pressure responses and two 504 timeout responses; body and token caps returned 413 and 400. Real health, explicit evaluation-only routing and atomic rollback also passed. The evaluation alias deliberately served the same immutable base tensor; no distinct candidate canary or quality result is claimed. See `reports/model-qa.md` and `reports/serving-smoke.md` for the exact commands and raw artifact locations.

## Full offline round orchestration

The CLI delegates its offline round to `src/cli_demo.rs`. It verifies local model assets, exercises a real base HTTP endpoint, restores a checksum-verified OCI archive if the configured sandbox image is absent, and replays/regrades the exact recorded fleet. The attempt ledger receives an immutable complete job plan before any provider dispatch, including eligible failover keys. Curation and training proceed only after those real prerequisites pass.

Regrading creates new truthful run IDs. Repeated demos therefore retain the original validated `data/curated` dataset referenced by completed checkpoints, and store fresh curation under `data/regraded/<row-artifact-hash>`. Reuse requires equality of the source/task/specification, prompt, chosen code, canonical provider request, permission decision and recorded provider artifact. Original run IDs are never invented to make a dataset hash stable. A genuinely different winner or changed evidence stops reuse and requires a new planned round.

All four genuine adapters are trained or fully validated before held-out access. The default full mode creates an execution UUID and writes actual optimiser outputs under `checkpoints/retrained/<execution-UUID>/<label>`, which is included in the delivery. A durable pointer under `state/demo-training/`, keyed by the original dataset/index, base/tokeniser and all four configuration hashes, identifies only that installation's resumable work. A process lease prevents concurrent full runs sharing the allocation; a matching allocation marker and checks rejecting symbolic links prevent accidental adoption of unrelated outputs. A fresh delivery has no application-state pointer and therefore performs optimisation even when bundled adapters exist. Restart may reuse its own validated completed work or resume the last durable optimiser step. Clearing application state causes another genuine training execution and preserves previous immutable checkpoints.

Completed outputs are accepted only when their seed, purpose, target transform, full configuration hash, original dataset/index hashes and actual tensor evidence match. The explicit `--use-recorded-checkpoint` fast mode requires all four real checkpoints and labels training as skipped. It reads the once-published path/tensor map in `checkpoints/demo-published.json`; older bundles without that map use `checkpoints/candidate`, `checkpoints/seed-control`, `checkpoints/degraded` and `checkpoints/overfit`. Full mode never chooses those bundled paths. The path selection and ownership rules are implemented and tested in `src/demo_checkpoint_paths.rs`.

`reports/model-freeze.json` fixes the primary candidate, all control tensors, configurations, corpus, inference parameters and gate before development evaluation. Verified base/candidate development outcomes then supply paired decoding-seed discordance, source effects/variance and a documented ANOVA-style source-correlation estimate. The configured actual gate is simulated over a predeclared sensitivity grid including conservative alternatives; decoding repeats are not counted as extra independent sources. The calibration and power report hashes enter `reports/round-freeze.json` before any held-out generation. Calibration cannot change the candidate, seeds or promotion thresholds. The small, single-author development set makes the correlation estimate fragile, so the report retains the sensitivity grid and its limitations.

The round then evaluates base/overfit training behaviour and the base, primary, degraded, overfit and second-seed held-out checkpoints through the same controller, using the selected allocation paths throughout development, train, held-out and endpoint phases. Complete cached evaluations must verify their tensor identities, exact split/coverage, decoding parameters, source/grader/security artifacts and freeze timestamps. The immutable model freeze uses tensor/data/configuration identity rather than allocation paths: bit-identical retraining may reuse original sealed observations, whose original checkpoint paths remain included and unchanged. Retraining that produces different tensors fails the existing freeze before development or held-out access; it cannot overwrite the freeze or silently replace evaluations. An interrupted evaluation with a preregistration but no complete manifest is explicitly blocked; it is never silently regenerated as a fresh sealed evaluation. The real control drills inspect the observed patterns rather than assuming that corrupted targets or extra training must produce them.

The primary gate report and actual control summary are written separately. A genuine candidate HTTP endpoint is smoke-tested for evaluation without changing production routing; NO SHIP retains the production incumbent. Missing provider data, a failed model step, invalid evaluation, endpoint failure or failed security handling remains a failing full command, with INVALID EVALUATION and partial phase reports. A separate disconnected clean-directory rehearsal is still required before claiming the delivery package is fully reproduced.
