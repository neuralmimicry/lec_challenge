# Repository instructions

Use Rust for application logic, candidates, training, statistics and tests. Any exception needs a concrete justification in docs/deviations.md. Use UK British English in prose and comments.

Read assessment-prebuild/JETBRAINS_BUILD_BRIEF.md, docs/design.md, docs/acceptance.md and agents/PLAN.md. User instructions override the pack's suggested Python stack. Keep modules small and public interfaces explicit; use bounded asynchronous I/O and move blocking compute/database work off async executor threads.

Never invent provider calls, usage, spending, weights, improvement, execution traces or successful drills. Explicitly label fixtures and fault injections. Fail closed on absent recordings, incomplete evaluations, unresolved rights, invalid artifacts or unenforced sandbox controls. Preserve failed observations in denominators and reports. Do not run untrusted candidates on the host.

Coordinate edits by ownership in agents/PLAN.md. Do not overwrite another agent's modules. Update STATUS.md and documentation with measured evidence. Unit tests for real invariants and adversarial integration tests accompany important changes; avoid tests that simply restate implementation.

Do not print credentials, publish the repository or send communications. Paid calls require explicit budget authority and applicable provider terms. Public open-source dependency/model downloads for the requested build are allowed. Record asset checksums and licences for offline packaging.
